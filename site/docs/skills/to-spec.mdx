# to-spec

<SkillHeader category="Hauptfluss" githubPath="engineering/to-spec" />

**Synthese, kein Interview.** Verwandelt das bereits Besprochene in eine strukturierte Spec und veröffentlicht sie im Issue-Tracker — ohne noch einmal nachzufragen, was längst geklärt ist.

## Wann nutzen

- Direkt nach `grill-with-docs`, sobald die Idee im Gespräch ausreichend geschärft ist und mehrere Sessions zur Umsetzung braucht.

## Wie es funktioniert

  eyebrow="Ablauf"
  steps={[

Die Spec folgt einem festen Template: **Problem Statement**, **Solution**, eine lange nummerierte Liste an **User Stories** (`Als <Rolle>, möchte ich <Feature>, damit <Nutzen>`), **Implementation Decisions** (Module, Interfaces, Architektur — ohne konkrete Dateipfade, die schnell veralten), **Testing Decisions** und **Out of Scope**.

## Gut zu wissen

Kam eine Entscheidung aus einem `prototype` (z.B. eine Zustandsmaschine oder ein Schema), darf genau dieser entscheidungsreiche Ausschnitt zitiert werden — nicht die komplette Demo, nur der Teil, der eine Entscheidung präziser festhält als Prosa es könnte.
