# Welcher Skill passt zu meiner Situation?

## Was ist ein Skill?

Ein Skill ist eine wiederverwendbare, in Markdown geschriebene Anleitung, die Claude selbst nachschlägt oder die du per Namen aufrufst — je nachdem, ob er *user-invoked* oder *model-invoked* ist (dazu unten mehr). Er kapselt eine bestimmte Denk- oder Arbeitsweise, damit du sie nicht bei jeder Aufgabe neu erklären musst.

## Wie gehe ich vor?

Die wichtigste Frage zuerst — und sie hat keine einzige richtige Antwort, sondern hängt davon ab, **wie groß und wie klar deine Aufgabe schon ist**:

## Drei Beispiele, eine Welt

Alle drei Beispiele spielen im selben (fiktiven) Produkt, damit der Größenunterschied greifbar wird — nicht weil das eine zwingend aus dem anderen folgen *muss*. Die meisten Features entstehen ohne vorheriges Epic; das dritte Beispiel zeigt nur, dass es *manchmal* zusammenhängt.

### Winzig: ein Formatierungsfehler

> *"Die Digest-E-Mail zeigt das Datum als MM/DD an, wir wollen DD.MM."*

<FlowRow
  eyebrow="Winzig"

Kein `to-spec`, keine Tickets — die Klärung ist in einem Satz erledigt, dann wird direkt umgesetzt.

> *"Wir wollen ein komplettes Selbstbedienungs-Portal für Enterprise-Kunden einführen."*
